Concepts

The networking and USB ideas behind the design: protocol layers, Ethernet frames, why the modem must do NAT, how DHCP and ARP cross a Layer 2 device, how a phone looks like a network card, and how Wi-Fi security fits in.

2.1Protocol layers

Definition 2-1: Layer 2 device

A device that moves Ethernet frames by MAC address only. It never reads or changes IP headers, so it needs no IP address, no routing table and no NAT. A switch, a bridge and the L2 dispatcher are Layer 2 devices.

2.2Ethernet frame

Everything the dispatcher handles is one of these frames. It reads only the first 14 bytes (the header) and passes the rest unchanged. The preamble and the frame check sequence (FCS) are added and removed by the hardware, so a raw socket never sees them.

The dispatcher uses the multicast bit test (ether_dhost[0] & 1) to decide whether a frame from the modem is counted for one client or just forwarded.

2.3Why the modem must do NAT

The operator gives one public IPv4 address per SIM. Four clients need four addresses, so something must translate. NAT (network address translation) maps many private addresses to one public address by rewriting the source address and port of each outgoing packet and keeping a table to reverse it for the replies.

A Layer 2 device cannot do this, by definition: it does not touch IP headers. So NAT and DHCP must live in the modem, and the modem must support several hosts behind its USB link ("router mode"). This was risk 1 and risk 2 in the plan, and both passed with the phone.

IPv6 needs no NAT

The phone hands out a public /64 prefix. Each client builds its own global IPv6 address from it (SLAAC), so IPv6 works end to end through a pure Layer 2 path.

Figure 2-3: Address view, one SIM and several clients

2.4DHCP and ARP across a Layer 2 device

A new client has no address yet, so it shouts: DHCP Discover goes to the broadcast MAC ff:ff:ff:ff:ff:ff. The dispatcher forwards it to the phone, the phone's DHCP server answers, and the reply comes back the same way. ARP works the same way: "who has 192.168.56.11?" is a broadcast, the answer is unicast. If broadcast frames were dropped, no client could ever get an address.

Figure 2-4: DHCP "DORA" exchange through the board

2.5A phone as a USB network card

USB defines device classes. For networking, the phone or modem presents itself as an Ethernet adapter and carries whole Ethernet frames inside USB bulk transfers. Linux turns it into a normal interface (usb0, renamed enu2).

ClassUsed byLinux driver
RNDISMost Android phones (Realme, Samsung)rndis_host
CDC-ECMQuectel EC25 (AT+QCFG="usbnet",1)cdc_ether
CDC-NCMNewer phones and modemscdc_ncm
QMI / MBIMModems in raw-IP modeNot used: no Ethernet header, no NAT

All of them sit on usbnet. Data flows as bulk IN (Bi, phone to board) and bulk OUT (Bo, board to phone). An interrupt endpoint (Ii) tells the host that data is waiting.

2.6Raw sockets and promiscuous mode

An AF_PACKET socket bound with ETH_P_ALL receives every frame on one interface, header included, before the IP stack. The kernel marks each frame with a packet type:

sll_pkttypeValueMeaning
PACKET_HOST0To this interface's MAC
PACKET_BROADCAST1To everyone
PACKET_MULTICAST2To a group
PACKET_OTHERHOST3To another MAC (needs promiscuous mode)
PACKET_OUTGOING4Sent by this host

Frames from the phone are addressed to the clients' MACs, not to the board, so enu2 must be promiscuous or they would be filtered out. PACKET_IGNORE_OUTGOING (socket option 23) stops the socket seeing its own transmits, which would otherwise loop forever between the two interfaces.

2.7Wi-Fi access point and the WPA2 handshake

In WPA2-PSK, the password never travels over the air. The access point and the client prove they both know it in a 4-message exchange carried in EAPOL frames (EtherType 0x888E). The result is a per-client session key used to encrypt that client's traffic.

On this board, hostapd runs the access point side. The handshake belongs between the client and hostapd, so the dispatcher must keep EAPOL frames away from the modem. After the handshake, the WILC3000 decrypts frames and delivers plain Ethernet frames on wlan0.

Client to client

Two clients on the same AP talk through the access point itself, so their frames do not need to cross the dispatcher.

EHCI Crash and Fix

The SAMA5D2 USB 2.0 host controller died about 1 s after the phone's network interface came up. The cause was the at91 CPU idle state RAM_SR; booting with cpuidle.off=1 fixes it.

PurposeTheoryImplementationResult
Make the USB 2.0 link to the modem stable.EHCI moves data by DMA into DDR; DDR in power-down cannot serve it.Kernel option cpuidle.off=1 saved in the U-Boot environment.No HC died; 480 Mbps, DHCP and Internet through the phone.

5.1Background: EHCI, its companion, and DMA

A USB 2.0 host port on this chip has two controllers behind it. EHCI handles High-Speed devices (480 Mbps). OHCI is its companion for Full- and Low-Speed devices (12 / 1.5 Mbps). When a device connects, EHCI tries the High-Speed handshake. If that fails, or if EHCI is not running, it sets the port owner bit and the port goes to OHCI.

Neither controller copies data through the CPU. They read transfer descriptors and data buffers directly from DDR by DMA. If a DMA access fails, EHCI sets the Host System Error bit (STS_FATAL, USBSTS bit 4), halts, and Linux reports fatal error and HC died. It then routes every port to OHCI (CONFIGFLAG = 0).

cpuidle picks a low-power state whenever the CPU has nothing to do. On SAMA5D2 the second state, RAM_SR, also puts the DDR controller into power-down until the CPU wakes. Bus masters such as EHCI are expected to wake it again, but here that did not work reliably: a USB DMA arriving in that window failed.

5.6Root cause

Table 5-4: cpuidle states before the fix (at91_idle)

StateNameDescriptionUsage seen
state0WFIWait for interrupt3716
state1RAM_SR"WFI and DDR Self Refresh"1403
 
/* arch/arm/mach-at91/pm.c */
static void sama5d3_ddr_standby(void)
{
    saved_lpr0 = at91_ramc_read(0, AT91_DDRSDRC_LPR);
    lpr0 = saved_lpr0 & ~AT91_DDRSDRC_LPCB;
    lpr0 |= AT91_DDRSDRC_LPCB_POWER_DOWN;
    at91_ramc_write(0, AT91_DDRSDRC_LPR, lpr0);
    cpu_do_idle();
    at91_ramc_write(0, AT91_DDRSDRC_LPR, saved_lpr0);
}

When the CPU idles in RAM_SR, the DDR controller is set to power-down. USB DMA that arrives in that window fails, and the kernel reports fatal error (EHCI Host System Error interrupt, ehci-hcd.c). With cpuidle.off=1 the at91_idle driver is not loaded (/sys/devices/system/cpu/cpuidle/current_driver is missing).

Workaround, not a final fix

Idle power is probably somewhat higher (to verify). Report to Microchip as a possible SAMA5D2 erratum and ask for a fix that keeps RAM_SR (MCU Option tab, questions to Microchip).

L2 Dispatcher (l2disp)

A single-threaded C program that opens one AF_PACKET raw socket per interface and copies every Ethernet frame to the other side, except the Wi-Fi handshake, which stays with hostapd.

PurposeTheoryImplementationResult
Replace the kernel bridge with a small program we control.Two raw sockets see whole frames; forwarding both ways is a Layer 2 bridge with two ports.l2disp: poll() loop, EAPOL filter, reconnect, per-client counters.Same result as br0, about 13 Mbps, starts at boot.

7.2Design reasoning

Table 7-1: Choices and the reason for each

ChoiceReason
User space, not a kernel moduleEasy to debug and update, no kernel rebuild; CPU load is ~0 % at the measured rate
AF_PACKET, ETH_P_ALLSees every frame with its header, before the IP stack; no IP needed on the interface
One poll() loop, one threadOnly two file descriptors; no locking; frame order kept per direction
No MAC learning tableOnly two ports: every frame from one side goes to the other, so there is nothing to decide
Promiscuous on enu2 onlyFrames from the modem carry client MACs; on wlan0 the AP already delivers client frames
EAPOL kept localThe WPA2 handshake is between client and hostapd (Concepts tab, 2.7)
Static binaryNo dependency on the board's C library version

8.8Glossary

TermMeaning
AF_PACKETLinux socket family that sends and receives whole Ethernet frames on one interface
AP / SoftAPAccess point: the side of a Wi-Fi network that clients join. SoftAP = AP run in software on a host
ARPAddress Resolution Protocol: finds the MAC address for an IPv4 address (broadcast question, unicast answer)
Bridge (br0)Linux kernel Layer 2 switch between interfaces; the stand-in for the dispatcher in step 5
Bulk transferUSB transfer type for large data; carries the Ethernet frames (Bi in, Bo out)
CDC-ECM / CDC-NCMStandard USB classes for Ethernet over USB (ECM: one frame per transfer, NCM: several)
cpuidleLinux framework that picks a low-power state when the CPU has nothing to do
DHCPDynamic Host Configuration Protocol: hands out IP addresses (Discover, Offer, Request, Ack)
DMADirect memory access: a peripheral (here the USB controller) reads and writes RAM without the CPU
EAPOLEAP over LAN, EtherType 0x888E: carries the WPA2 key handshake
EHCIEnhanced Host Controller Interface: the USB 2.0 High-Speed (480 Mbps) host controller
EtherType2-byte field in the Ethernet header that names the payload protocol
FDBForwarding database: a bridge's table of which MAC lives on which port
FIT image (.itb)U-Boot Flattened Image Tree: one file holding the kernel, device tree and overlays
GROGeneric Receive Offload: the kernel merges received packets; turned off on enu2 so merged frames are not too big to send
hostapdLinux daemon that runs a Wi-Fi access point and its security handshake
HSICHigh-Speed Inter-Chip: a USB 2.0 link between chips on a board, without a connector
MAC address48-bit hardware address in every Ethernet frame (destination, source)
NATNetwork Address Translation: lets many private addresses share one public IPv4
OHCIOpen Host Controller Interface: the USB 1.1 (12 Mbps) companion controller
Port ownerEHCI PORTSC bit that hands a port to the companion (OHCI) controller
Promiscuous modeAn interface accepts frames for any MAC, not only its own
RAM_SRat91 cpuidle state "WFI and DDR Self Refresh"; puts DDR into power-down while idle; cause of the EHCI crash
RNDISMicrosoft's Remote NDIS: Ethernet over USB, used by Android tethering
SLAACStateless address autoconfiguration: an IPv6 client builds its own address from the router's prefix
usbmonKernel tracer that logs every USB transfer (S submit, C complete)
usbnetLinux base driver shared by RNDIS, ECM and NCM; manages the USB transfer queues
VBUSThe USB 5 V supply line; the host must switch it on for the device
WILC3000 / WILC1000Microchip Wi-Fi link controllers that pass raw frames to a host driver
WPA2-PSKWi-Fi security with a pre-shared password and a per-client AES-CCMP key

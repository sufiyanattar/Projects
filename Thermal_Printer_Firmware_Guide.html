Smart Batch Algorithm

How every print line is split into heat groups of at most 64 dots, and how those groups are fired in two passes while the paper motor moves.

4.1The problem it solves

A thermal head makes a dot by passing current through a heat element for a few hundred microseconds. All 384 elements of a line share one VP supply. Each active element draws VP / R, so the current grows with the number of dots heated at the same time.

Table 4-1: Peak head current, I = N × VP / Rmin (datasheet equation 2, Rmin = 166 Ω)

Dots heated at once (N)VP = 9.0 VVP = 9.5 VComment
64 (one block)3.47 A3.66 ASmart batch maximum
965.20 A5.49 ADatasheet limit for simultaneous dots
1286.94 A7.33 ADatasheet limit only if VP ≤ 7.9 V
384 (whole line)20.82 A21.98 ANot allowed

The simplest safe method fires the six blocks one after another, six heat cycles per pass. That wastes time when a block holds only a few dots. Smart batch puts several partly filled blocks into one heat cycle, as long as the group stays at or below 64 dots. A line of short text often needs one heat cycle instead of six.

The whole line is shifted in and latched once (SPI1_ByteExchange() × 48, LAT high 1 µs, low, wait 10 µs). After that, the latched data stays in the head and the firmware only switches strobes. A strobe heats only the dots that are 1 in its segment, so the pixel count of a segment (count_segment_pixels(), a bit count over 8 bytes) tells how much current that strobe draws.

In code the segments are numbered 0–5; this page uses S1–S6 to match DST1–DST6.

How to read the timeline

Each step starts with a 2 µs motor pulse and starts SCCP1 (250 µs). The groups of that half heat one after another. The step ends when both the heating and the motor timer are done (while (!MotorTimer_IsDone())), so a step lasts at least 252 µs and longer when there is more to heat.

Splitting into halves spreads the heating of one dot line over its four motor steps. A segment in Half 1 is heated in steps 1 and 3, a segment in Half 2 in steps 2 and 4, so between its two pulses each element gets the other half’s time to cool.

When n = 1, Half 2 is empty: steps 2 and 4 are motor-only (252 µs). The same elements then fire again after only the cooling time plus one bare step. For a short text line this gap is 334 µs, below the datasheet’s 0.5 ms minimum pause (finding F2). The simulator in 4.6 shows this value as “shortest element pause”.

Heat Timing

Formulas, constants and hardware timers that set how long each group heats, cools and waits for the motor.

5.1Heating time per group

// calculate_heating_time(p = group pixels)
t = base_heating_time_us + p * heating_per_pixel_us;  // 150 + 8p
if (p > 32)                                          // thermal mass
    t = t * (100 - (p - 32) * 5 / 32) / 100;          // 100 % .. 95 %
t = t * density / 100;                                // DC2 ~ n
t = clamp(t, 200, 650);                               // min / max
t += warmup_boost;                                    // solid lines

Heat time grows with the dot count of the group, because a fuller group pulls VP down and each element gets a little less power. Above 32 dots the time is cut by up to 5 % because neighbouring dots share heat.

5.6Comparison with the datasheet method

The datasheet (section 3.5) calculates the pulse width from paper energy E, adjusted resistance R, drive voltage V, head temperature (thermistor) and activation cycle: t = E × R / V² × C. The firmware uses a fixed linear formula per dot count and does not correct for measured VP or head temperature. Speed, temperature and supply changes are therefore not compensated (open item in Status).

7.6GS Y 5 BMP print

  1. Host sends 1D 59 05 followed directly by the BMP file (the terminal does this; the comment block in code describing status, size and ACK steps is not what the code does).
  2. Firmware reads the 54-byte header: signature “BM”, pixel offset, width, height, bits per pixel.
  3. Rejects anything other than 1 bit per pixel and width 384.
  4. Reads the 8-byte palette; if colour 0 is black, pixels are inverted so 1 = black.
  5. Rows are 52 bytes (padded to 4). Only the top 200 rows (CHUNK_LINES) are kept; extra bottom rows are read and dropped.
  6. Each row is mirrored (byte order and bit order reversed) into buffer_A, bottom-up order corrected.
  7. All rows are printed after the whole file is received, then 100 feed steps.
RAM use

buffer_A (200 × 48 = 9600 B) is shared by GS Y 0, GS Y 2 and GS Y 5. GS Y 1 has its own 10 × 48 static buffer.

Glossary

Terms used in this guide, the source code and the print mechanism datasheet.

Dot lineOne horizontal row of 384 dots, 0.125 mm tall; 48 bytes of data.
Segment / block64 adjacent dots (8 bytes) switched by one strobe; S1–S6 here, segment 0–5 in code.
DST / strobeHead input that powers the latched dots of one block while high. DST1–6 on RB8, RB9, RC4, RC5, RC10, RC11.
LATLatch input (RA4). Pulsed after the 48 SPI bytes so the head holds the line while the strobes fire.
DI / CLKHead serial data and clock, driven by SPI1 SDO (RC9) and SCK (RC8).
VPHead and motor supply, about 9 V, switched by SUPPLY_EN (RB13).
Heat groupStrobes fired together in one heat cycle; at most 64 dots in total.
Half 1 / Half 2The first ⌈n/2⌉ groups and the rest; Half 1 fires in steps 1 and 3, Half 2 in steps 2 and 4.
PassOne heating of every group. Each dot line gets two passes.
Recovery time50 µs extra off-time after a full 64-dot group (inter_batch_cooling_us).
Warm-up boostUp to 450 µs added to the first 10 solid lines of a job.
DensityDC2 ~ n, 10–150 %, scales heat time before the 200–650 µs clamp.
Activation cycle WDatasheet term: time between the starts of two activations of the same element; must exceed t + 500 µs.
SCCPSingle-capture/compare/PWM timer. SCCP1 motor, SCCP2 heat, SCCP3 cool.
XON / XOFF0x11 / 0x13 bytes sent by the printer to resume / pause the host (ESC F 1).
RTS / CTSHardware flow lines: printer RTS on RD8 (low = ready), CTS input on RD10 (ESC F 2).
Ring buffer1024-byte UART receive buffer filled by the RX interrupt.
GS v 0Standard ESC/POS raster image command: 1D 76 30 m xL xH yL yH + data.
ACK0x06, sent by the printer in GS Y modes when ready for the next batch.
ShirorekhaThe horizontal head line of Devanagari script; rows 7–8 of the 37-row glyph.
MatraDevanagari vowel sign joined to a consonant; stored as pre-composed glyphs.
MCCMPLAB Code Configurator; generates the drivers in mcc_generated_files/.
FRCInternal 8 MHz fast RC oscillator; multiplied by the PLL to FOSC 12 MHz.
ppsPulses (motor steps) per second; datasheet maximum 3200.
